01

システムの目的と対象

自分のPDFを、自分に合った学習コースへ。教材を登録し、理解・練習・対話・評価・復習を同じ場所で続ける。

Study-with-AIは、Mac上で動かすStreamlit製のローカルWebアプリです。ブラウザを操作画面とし、PDFの読み取り・検索・進捗保存をローカルで行います。回答や講義などの文章生成だけを、ChatGPT認証済みの公式Codex CLIへ依頼します。

INPUT

自分の教材

カテゴリ・科目ごとにまとめたPDF。テキスト層を優先し、一部の画像ページはOCRの対象になります。

PERSONALIZE

自分の学び方

到達目標、前提知識、例題重視、たとえの分野、1章のインプット時間の目安を指定します。

LEARN

学習を続ける

カリキュラム、講義、相談、試験、採点、弱点の復習と進捗をつなげます。

対象と設計範囲

  • 個人が自分の端末で使用する学習環境。公開SaaSや、アカウント権限を持つ複数利用者向けシステムではありません。
  • アプリ側からOpenAI APIを直接呼び出しません。公式CLIは生成のためOpenAIサービスへ通信します。
  • 生成モデルはgpt-6-astra、reasoning effortはmedium固定です。
  • 教材の一部を選んで生成へ渡す方式です。PDF全文の完全な読解・網羅、学習効果や採点精度の保証ではありません。

02

学習の全体フロー

PDFの登録だけでは生成は始まりません。利用者が各生成ボタンを押したときに要求を作成します。

  1. 01 · 教材を置くアップロード、またはFinderでカテゴリ／科目フォルダへ配置。
  2. 02 · 索引を作るローカルでページを抽出し、検索できる状態へ。
  3. 03 · 学び方を決める目標・既知の内容・例題・たとえ・時間を保存。
  4. 04 · コースを作るテーマと5／10／15章を指定してカリキュラム生成。
  5. 05 · 一章ずつ学ぶ講義を読む、例題を試す、分からない点を相談。
  6. 06 · 確認して復習試験・採点・章修了・次章、または弱点を復習。

生成する操作／しない操作

操作Codexによる文章生成主な処理
起動、画面移動、科目選択、履歴表示なし保存済み情報を読む。起動時にログイン・索引作成・重み読込を一括実行しない。
PDF登録、索引更新、ローカル検索なしローカルPDF抽出、E5／BM25検索。
学び方保存、質問候補の選択なし設定・下書きを保存。候補は明示送信を待つ。
カリキュラム、講義、相談、傾向分析、問題、採点あり共通Service → ジョブ → Codex Provider。利用枠を消費し得る。
診断なし公式CLIの認証・モデル一覧・実効設定を照合。通信を伴う可能性はある。
完了結果の再表示、進捗再開なし保存結果・receiptを使用し、再生成・二重加点を防ぐ。

03

教材登録とFinderからの操作

教材の置き場所と、その後に押すボタンを明示します。

保存先の規則

既定ルートはリポジトリのdata/です。科目を識別するのはカテゴリ／科目の2階層です。科目フォルダの中にあるPDFを対象とし、その下のサブフォルダも検索対象になります。同じ科目名でもカテゴリが異なれば別科目です。

/Users/shinrisuzuki/Developer/projects/Study-with-AI/data/
└── 数学/
    └── 線形代数/
        ├── 教科書.pdf
        └── 演習問題.pdf

Finderで直接置いた場合

  1. Finderで⌘⇧Gを押し、~/Developer/projects/Study-with-AI/dataを開く。
  2. 「数学」→「線形代数」のようにカテゴリ・科目フォルダを作り、PDFを入れる。
  3. アプリを開き、ブラウザを⌘Rで再読み込みする。
  4. 左メニューの「教材ライブラリ」を開く。
  5. 「登録済みの教材」で該当科目を開き、PDFのファイル名を確認する。
  6. 「ローカル索引を構築・更新」を押す。読み取り完了を待つ。
  7. 「この科目を学ぶ」を押し、「あなたの学び方を設定」で希望を保存する。
  8. 「新しいコースを作成」で学習テーマ・章数を指定し、「カリキュラムを作成」を押す。

「ローカルEmbedding + BM25の索引を確認しました」または「BM25検索を利用できます」の表示で、検索を使える状態です。BM25のみでも学習できます。Finderに置いたPDFをアップロードし直す必要はありません。

ブラウザからアップロードする場合

「教材ライブラリ」の「登録先（カテゴリ/科目）」を入力し、1つ以上のPDFを選び、「教材を保存」を押します。同名ファイルは上書きしません。複数ファイルの一部が失敗した場合、保存できた教材を保持して個別エラーを表示します。保存後の「この教材でコースを作る」で学習へ進めます。

認識しない配置

  • data/教材.pdfやdata/線形代数/教材.pdfのように、カテゴリ／科目の階層が不足している。
  • ドットで始まるカテゴリ・科目、symlink（シンボリックリンク）、教材ルート外へのパス。
  • PDF以外のファイル。暗号化・破損など、読み取りできないPDF。
PDFを追加・変更・削除すると教材revisionが変わります。進行中の古い要求の反映や、古い講義を使った出題は停止することがあります。科目名・フォルダ名の変更も教材識別に影響するため、既存コースの関連付けが自動移行されるとは扱わないでください。

生成中は待機状態とキャンセルを表示し、2秒間隔のStreamlit fragmentで既存ジョブの状態を確認します。完了結果を反映して画面を更新します。この定期処理は生成要求を追加しません。

05

個別化・授業設計

学習者の希望は生成方針へ反映しますが、根拠・採点規則・実行境界を上書きする指示にはしません。

設定入力・選択肢反映の仕方
学習ゴール文章、最大1,200文字できるようになること、カリキュラムの到達像、学習の位置づけ。
既知の内容・苦手文章、最大1,200文字説明の出発点。本人申告として扱い、未知の知識を既知と断定しない。
学び方体系的に理解／例題を多く解く／実践・プロジェクト／試験に備える概念の関係／手順と条件違いの練習／成果物や確認基準／想起や典型問題を重視。
たとえの分野文章、最大300文字料理・音楽などとの対応と、そのたとえが成立しない範囲を示す。
1章のインプット時間の目安15／25／45／60分、既定25分講義を読む・導出や解説付き例題・コードを追う時間。練習・試験・復習は別枠。時間に合わせて説明を省略しない。
説明の詳細初心者／専門家、簡潔／普通／詳細、4種類のスタイル、数式導出説明の粒度、直感・厳密さ、ソクラテス式のヒントなど。
検索件数1〜10、既定5質問検索で要求する抜粋数。コース代表抜粋には別の最低要求数がある。

設定の保存範囲

科目別の学習プロフィールはlearning.sqlite3に保存します。科目未選択で保存したプロフィールは、その科目に独自設定がない場合の既定値になります。説明対象・長さ・スタイル・検索件数は現在の共通UI設定と組み合わせます。新しいコースには要求時の設定一式を保存し、そのコースの講義・対話に再利用します。後からプロフィールを変えても、作成済みコースの方針は自動変更しません。修了試験の難易度は明示選択でき、採点は生成した試験の難易度を引き継ぎます。

講義に求める構成

到達目標 → 前提・用語・記号 → 概念と理由 → 数式と途中の導出 → 図解・数値例・解説付き例題 → 適切な分野の実装コードと理論の対応 → 誤解・適用条件・限界 → 要点整理。章の計画と最大8節で説明をつなげます。計画の構成・目標・参照は検証しますが、実際の教育品質を機械的に保証するものではありません。

自分で解く問題は専用の練習タブへ分離します。練習と正式試験の採点は別です。本文に「正解」「修了」と書かれただけでEXPや章完了は発生しません。

旧設定との区別

新規はtime_scope=lecture_input、非空の旧保存設定に識別値がない場合はlegacy_total。旧60分を無言で読み替えません。「新方式の講義を作る」で現在の章立て・目標を使い、新版の生成条件だけを変更します。旧カリキュラムの時間配分文は履歴として保持します。

Deep Learningの実装例

誤差逆伝播なら計算グラフ、連鎖律、局所勾配、逆向き伝播、パラメータ更新、数値例、Python／NumPyコードまで説明をつなげます。必要に応じてPyTorchに対応付けます。非プログラミング科目にはコードを強制しません。教材にない前提やコードは一般的補足とし、実行確認済みとは表示しません。

06

生成機能と出力契約

11種類の生成を同じService・Providerへ集約し、形式と業務上の整合性を確認してから保存します。

kind目的生成JSONの主要フィールド
answer教材に基づく質問回答markdown / source_ids / supplemental_markdown / insufficient_evidence
lecture章の自習教材answerと同じ文章形式。本文・一般的補足・根拠不足を区別。
dialogue講義への質問・反論・ヒント同じ文章形式。会話履歴と選択講義contextを参照。
trend抜粋範囲の概念・出題傾向・優先度同じ文章形式。全文統計と称さない。
curriculum指定章数の順序立てchapters［chapter, title, description］/ source_ids
quiz試験を作成title / questions［id, prompt, max_points, rubric, model_answer, source_ids］
grade答案を設問別に評価items［question_id, points, max_points, reason, improvement, source_ids］/ feedback / weaknesses

形式と意味の検証

  • JSON Schemaの必須フィールド、型、文字数、件数を検証し、余分なフィールドを拒否します。
  • 教材の参照IDは、その要求で渡した集合に限定します。IDの実在検査と、文章の主張が教材に支持されるかの判断は別です。
  • カリキュラムは指定章数と連番、試験はIDの一意性と配点、採点は設問の重複・欠落と得点範囲を検証します。
  • 一般的補足はsupplemental_markdownへ分離。insufficient_evidence=trueなら根拠不足を表示します。
  • 検証後、アプリが教材revision・選択範囲・設定・要求識別情報などを付加します。

CLIへ送るSchemaと、戻り値のSchema

固定CLIとの互換性のため、送信用コピーからuniqueItems・minLength・maxLengthを除去します。元Schemaは変更せず、返ったJSONを元の厳しい制約で確認します。配列件数・数値範囲・必須キーなどは送信側にも維持します。不正な出力を自動修正・自動再生成して成功にしません。

追加の4契約

kind主要な契約
lecture_plantitle / objectives / prerequisites / requires_code / requires_math / sections / source_ids。節はs1から連続、最大8。
lecture_section本文・一般的補足・根拠とsection_id / summary（最大600文字）/ covered_objectives。要求した節・目標と照合。
practice_set3問固定。概念説明を1問以上。各問に学習目標、1〜3ヒント、解答・解説、確認基準、根拠。
practice_feedbackquestion_id / strengths / misconceptions / next_steps / review_topics / source_ids。得点・合否・EXPを含めない。

練習フィードバックは保存セット全体のscope・教材版・問題ID・根拠を検証後、対象1問と必要な根拠だけを送ります。保存原本を削らず、入力上限も引き上げません。

07

試験・採点・進捗

AIは設問別の評価を返し、合計点・合否・章完了・EXPはアプリが決定します。

難易度出題構成の生成指示配点合格点
Easy前10問は4択、残り5問は記述10問×5点 ＋ 5問×10点 = 10070点以上
Normal前5問は4択、残り5問は記述5問×4点 ＋ 5問×16点 = 10080点以上
Hard批判的分析・統合論述の4問20＋20＋30＋30 = 10090点以上

問題数・配点順・合計100点はコードで検証します。「4択として適切か」「論述の教育的難易度」「誘導の少なさ」などの内容品質は生成指示と点検の対象で、配点検証だけでは保証しません。

受験と採点の契約

  • 解答前の画面へ渡すのはタイトル、問題ID、問題文、配点だけです。模範解答・rubricを公開用projectionから除きます。
  • 答案は試験attemptごとに保存します。未採点の下書きがある試験の切替には確認が必要です。
  • 採点は元試験の科目・セッション・コース・教材revisionを照合します。配点の変更や、設問の欠落・重複を拒否します。
  • 各得点は0〜設問配点。アプリが加算し、試験難易度の閾値と比較します。モデルに総点や合否を決めさせません。
  • 章完了には合格attemptと、正しい章・保存講義ID・現教材revisionが必要です。章の修了で50 EXPを一度だけ付与します。

復習と学習記録

採点から最大3件の弱点を記録します。新たな弱点の復習予定は翌日、復習済み処理で次は3日後、次は7日後へ進み、最終段階の復習済み処理で弱点一覧から外します。再び指摘されるとレベル1へ戻ります。これは実装した復習スケジュールで、全員に最適な学習間隔を保証するものではありません。

25分のポモドーロ完了は20 EXPを一度記録します。途中中断は記録しません。学習日付はAsia/Tokyo。日次EXPと連続達成日を管理し、日付変更後に前日のEXPを当日の達成として数えません。

練習タブ

章全体または選択節から1セット3問を生成。ヒントは1段階ずつ、解答・解説は明示ボタンで表示します。表示時の追加生成はありません。答案を送ったときだけフィードバックを生成します。下書き・提出履歴・ヒント利用・解答開示状態・復習候補を保存し、やり直しでも提出履歴を保持します。生成コードの自動実行機能はありません。

版ごとの試験

旧版の合格を新版へ流用しません。従来の章修了・章解放・EXPは取り消さず、新版の受験で同じ章の50 EXPを重複加算しません。練習は合否・章解放・EXPへ影響しません。

構成とデータフロー

表示・学習規則・検索・生成・保存の責任を分け、UIから任意のコマンドを実行できる経路を設けません。

PDF抽出・ローカル検索

Embedding APIを使わず、日本語を考慮したキーワード検索とローカル意味検索を組み合わせます。

抽出と索引化

  1. 安全な科目パスのPDFを読み、同じバイト列から内容SHA-256と抽出結果を得る。
  2. ページのテキスト層を優先する。抽出文字数が20未満で画像を含む場合にOCRを試す。
  3. 原文を既定400文字、60文字重複でchunkへ分割。ページ番号と出典情報を保持する。
  4. Janome形態素・日本語bigram・英語単語を使うBM25索引を作る。
  5. 固定したローカルE5が利用できればベクトルも作成し、cosine検索とBM25をreciprocal rank fusionで統合する。

各抜粋に教材相対パス、document ID、内容hash、1始まりのページ番号、chunk ID、source IDを付けます。同名PDFを別科目と混同せず、引用可能なIDは要求ごとに確定します。壊れたPDFや読み取れないページは警告・エラーとして扱い、読めたものとして網羅率へ加算しません。

入力サイズの扱い

講義を除く要求を先に48,000 UTF-8 bytesで確認し、講義抜粋を加えたpayload全体も同じ上限で確認します。履歴内の表示・保存用assistant.resultは本文の重複を避けて計数前に除きますが、会話本文、未知metadata、user側のresultは制限対象です。20件やrevisionで絞る前の入力にも制限があり、長すぎる履歴を無条件に受理する仕様ではありません。

複数節の講義

各節の生成はその節のtitle/topicsで教材を再検索します。章全体の計画と先行節の要点を渡し、全文を連結しません。相談では指定節を優先。章全体の試験では節ごとの到達目標・本文・一般的補足に参照枠を分配し、合計6,000文字以内の抜粋にします。全講義を読んだ扱いにはしません。

ジョブ・キャンセル・再試行

一度送った要求の状態を保存し、画面更新や再起動で勝手に送り直さない。

queued→running→
succeeded / failed / cancelled

異常終了後に未完了だった要求はinterruptedとして復旧します。保存されるのは状態・要求・結果であり、実行用callableを再起動後に自動再実行する仕組みではありません。

性質実装上の約束
同時実行同じ保存領域で1件。複数タブ・複数processにもOSのflockを使用。別state領域とは共有しない。
二重送信防止scope別のpending確認、ジョブ登録、pointer保存をSQLiteの書込みロックでまとめる。
取消しcancel eventを伝達。Providerがその要求のprocess groupだけを停止・回収。他のCodexは停止しない。
期限生成180秒、診断全体15秒。期限超過時に成功結果として反映しない。
親の異常終了所有CLI子へlock FDを継承し、子が生きている間に次の生成枠が開かないようにする。
結果の適用job receiptとprogress eventを重複排除。同一IDで異なる結果を適用しない。
アプリ自動retry0回。失敗・中断は利用者の明示的な別要求なしに再投入しない。
CLI内部retry固定版の有限retryを許容。HTTP既定4、stream既定5は個別loopの値。無制限接続retry=false。
利用枠枠エラーでは停止。Resetを自動消費しない。別モデル・有料APIへ切り替えない。

成功の成立条件

CLI終了0、JSONLの完了イベント、最終メッセージ、JSON解析、元Schema、業務ルール、教材revision照合が必要です。固定版で確認した限定通知だけを許容し、未知のerrorやmodel reroute、tool使用、未完了出力を成功にしません。

1ジョブは「HTTP送信1回」「推論1回」「利用枠消費1単位」を意味しません。transport切替や認証回復を含む内部回数は不明です。キャンセル後にサービス側の処理・消費が必ずゼロになるとは保証しません。

章の一括作成

親ジョブ1件が設計1回＋本文最大8節を順番に実行し、章の作成中は既存の生成ロックを保持します。初回最大9要求、各要求180秒、開始・明示再開1回あたり全体30分です。設計後は節数と保存済み件数を表示。成功した節を逐次保存し、途中本文として読めます。

失敗・キャンセル・timeout・利用枠制限・教材変更で次へ進みません。再起動では自動再開しません。「未完了の節から再開」は成功節を再利用し、未完了・失敗した要求だけを新しい要求IDで実行します。明示再開の追加消費は初回9要求に含まれず、期限も再開ごとの30分です。自動再生成は0回。

要求の識別と再現

LearningRequestはrequest_id、kind、subject、session_id、course_id、material_revision、payload、options、sources、model、effort、prompt_version、schema_versionを持ちます。正規化したJSONからdigestを計算します。現在の生成指示版はstudy-4、出力契約版はstudy-3です。意図的な再受験・再生成は新しいIDになります。

保全の範囲

SQLiteはWALとバージョン検査を用い、DB作成権限は0600です。未知の未来版・破損を空データへ置換しません。旧JSONの未知フィールドや原文を保全して一度だけ移行します。今回のプロフィール等は既存documentへの追加であり、SQLite再移行は不要です。複数DBと任意の外部PDF変更を横断する完全transactionはないため、最終照合直後のファイル変更という短い競合窓は残ります。

講義版・練習の追加保存

章の現行版はlecture_content、旧版はlecture_versions。旧版の本文・相談・試験答案・採点・練習履歴は閲覧・書出しできます。未採点試験の正解を旧版の閲覧で開示しません。

相談・練習・試験は科目／セッション／コース／章／講義版で分離。練習は対象節・セットID・問題IDも区別します。講義バッチは章単位の共通pendingで二重開始を抑止し、版別checkpointと最新mirrorを同一transactionで更新します。既存テーブルへのdocument追加のみで、SQLite再移行はありません。

バックアップの対象

アプリを正常停止し、user_data/のDBと関連WAL/SHMを同じ時点の組としてGit外へ保管します。教材の復元が必要ならdata/も対象です。稼働中DBを単に1ファイルコピーすると、WAL内の最新変更が含まれないことがあります。進捗RepositoryにはSQLite online backupを使う方法もあります。

既知の制約・非対象

未確認の機能を確認済みとせず、現時点の適用範囲を明示します。

  • 直接RAG回答の実生成

    実装・mock検証はあるが、今回の実8ジョブでは成功未確認。コース内対話の実成功とは分ける。

  • 教材の網羅性

    代表抜粋・関連抜粋方式。全文・全論点・全ページを理解した保証ではない。大量PDFでの教育品質は未評価。

  • OCRと特殊教材

    画像PDFの実認識精度、複雑な数式・図表の理解を保証しない。OCRエラーは警告として残る。

  • 教育効果と採点

    人間による長期学習効果評価は未実施。生成問題と模範解答を使った小規模評価だけで一般的採点精度を保証しない。

  • OSと公開運用

    macOS arm64で検証。Linux未検証。WindowsはPOSIX lock/process groupのため未対応。インストーラもmacOS arm64用。多人数向け認証・公開配備は本仕様の対象外。

  • 処理・利用枠の観測

    CLI内部送信回数、サービス推論回数、要求別利用枠消費は不明。自動Resetはしない。

  • 整合性の境界

    異なるstate間で生成ロックを共有しない。外部PDF変更と複数DBを横断する完全transactionはない。孤立ジョブのPID再利用という稀な復旧制約がある。

  • 互換性

    複雑なMermaidはコード表示。SQLite→旧JSONの自動逆移行なし。固定CLIを更新する場合は実効設定・境界を再検証する。
